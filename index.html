1. 把经验留给下一次任务

RSI 是「递归自我改进」的缩写。每轮留下的变化会成为下一轮的起点。读研究时，可以再追问一句：变化影响的是做任务的能力，还是发现、验证和保留改进的能力？

Agent 修空购物车时，发现直接改代码容易漏掉折扣回归。它把有效的步骤写成 Skill，之后遇到同类任务就能加载这条方法。Skill 是可执行的做法，最好同时说明何时适用。

一条可复用的 Skill
修改订单金额计算时，先加一个能复现故障的测试，再做最小改动，最后跑折扣和退款的回归测试。

什么操作能让这次经验影响一个全新的会话？

2. 复盘与记忆维护

一次任务会留下输入、工具调用、输出和验证结果，这份记录通常叫 运行轨迹（rollout）。复盘时可以把轨迹里有长期价值的部分留下。事实记忆回答「现在是什么」，Skill 回答「这类任务怎么做」，原始轨迹则供以后核对。

购物车案例
付款规则迁移后，运费阈值由配置服务按地区返回。旧记忆却写着「满 99 元免运费」。这次修复可以把旧数字标记为已废弃，把「先查生效配置及地区」写入流程。一次工具调用结果只对应当时的环境，后续还要能定位它的版本。

判断是否值得记下来。 来源可信、以后还能用、适用范围明确的内容才值得长期保存。遇到两条冲突记忆时，先核对来源和生效时间，再更新对应条目，避免下次同时命中两条规则。

查到本周促销免运费，怎样留下最有用的记录？
旧记忆与新配置冲突，确认配置已正式迁移后应怎么办？

3. 让 Skill 增量演化

Skill 可以先覆盖最常见的工作，再根据反复出现的失败逐步修改。一个好改动应能写清触发条件、执行步骤、退出条件和可验证结果。多份相似 Skill 会争抢同一任务，合并前应检查各自独有的分支。

从 v1 到 v2
v1 每次只验证一种折扣。多条轨迹显示，当满减与优惠券叠加时，扣减顺序常写反。v2 只在存在两个及以上优惠时增加「列出叠加顺序并运行交叉用例」。简单购物车保留原来的短路径。

怎样管理库。 给候选版本记录失败证据和对照结果。若两个条目触发范围重叠，先比较哪些步骤共用、哪些结果需要单独验证，再决定合并或归档。

多个任务出现同一种叠加顺序错误，哪个修改最合适？
两份 Skill 描述相近，但其中一份有海外税费分支。整理时第一步做什么？

4. 用新题和旧题验证 Skill

拿没参与写 Skill 的题来对照。固定模型、工具和预算，让两组都做同一批题，只改变是否加载 Skill。记下修复成功率、回归失败数和耗时，再决定是否保留。

留出任务
用空购物车的问题提炼 Skill。把退款金额、叠加优惠和运费边界留到评测时再用。

旧任务用来查回归，新任务用来测迁移。两类分数单独报告。新题进步而旧任务退步时，先看退步是否触及预设的关键保障项。

哪种实验更能说明 Skill 对新问题有效？

5. 把运行轨迹变成可重跑的题

一条线上轨迹可以提供题目线索。把它整理成评测题，需要固定输入、依赖数据或工具快照、独立核验的预期结果和评分规则，再按任务族划分开发集和留出集。

可以复跑的退款案例
输入是「订单原价 120 元，满减 20 元，两件商品各占一半，退其中一件」。题目附当时的优惠分摊规则快照。验收比较退款金额和账单一致性，评审用快照独立标注。写 Skill 时把这一组退款场景封存，避免相似记录跨到留出集。

区分验证信号。 工具调用成功只说明工具执行了。任务是否完成，要查退款金额、状态和不应被改变的订单记录。对外整理材料时只分享脱敏案例和可公开结果。

6. 用离线反馈搜索更好的 Skill

手工修改只有一个候选。离线优化可以从不同失败轨迹中提出多份候选，再在固定预算内反复比较。以课程介绍的 GEPA 为例，反馈可以包含对错分数和运行细节，帮助提出下一版修改。

两个候选
候选 A 优先修复叠加顺序，候选 B 优先检查退款边界。开发集上 A、B 各自擅长不同任务。保留各有优势的候选，按失败反馈继续搜索。候选选定后，在封存的题目上做最终验证。

把规则写在结果之前。 先确定搜索预算、评分口径和发布门槛，再跑对照。搜索过程只使用开发反馈，避免反复查看最终成绩后继续调参。

每次看到留出集分数后都改候选，会发生什么？
两个候选总分相同，但各自通过的任务不同，下一步怎样做？

7. 模型和 Harness 怎样一起改进

Harness 是模型做事时用的运行框架，决定如何组织提示、工具和执行流程。HELIX 的思路是让同一个模型试用多套 Harness，将验证过的成功、失败和改动记录整理成可训练的数据，再为更新后的模型重新评估 Harness。

回到购物车
同一个模型用两套流程修复相同的故障。一个补丁修了空购物车却破坏折扣，另一个通过了两类测试。这对带有验证结果的轨迹可以用于构建训练样本。

读论文时区分两种提升。 单个 Harness 的表现回答「部署一套流程能做到多少」。多个候选的合并覆盖率回答「这些流程加起来能解哪些题」，还涉及候选选择和额外算力。论文评估了一轮代码修复，并展示了可以构建的训练记录。查看实验摘要
