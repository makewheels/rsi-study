1. 把经验留给下一次任务

RSI 是「递归自我改进」的缩写。每轮留下的变化会成为下一轮的起点。读研究时，可以再追问一句：变化影响的是做任务的能力，还是发现、验证和保留改进的能力？

Agent 修空购物车时，发现直接改代码容易漏掉折扣回归。它把有效的步骤写成 Skill，之后遇到同类任务就能加载这条方法。Skill 是可执行的做法，最好同时说明何时适用。

一条可复用的 Skill
修改订单金额计算时，先加一个能复现故障的测试，再做最小改动，最后跑折扣和退款的回归测试。

什么操作能让这次经验影响一个全新的会话？

2. 用新题验证 Skill

拿没参与写 Skill 的题来对照。固定模型、工具和预算，让两组都做同一批题，只改变是否加载 Skill。记下修复成功率、回归失败数和耗时，再决定是否保留。

留出任务
用空购物车的问题提炼 Skill。把退款金额、叠加优惠和运费边界留到评测时再用。

哪种实验更能说明 Skill 对新问题有效？

3. 模型和 Harness 怎样一起改进

Harness 是模型做事时用的运行框架，决定如何组织提示、工具和执行流程。HELIX 的思路是让同一个模型试用多套 Harness，将验证过的成功、失败和改动记录整理成可训练的数据，再为更新后的模型重新评估 Harness。

回到购物车
同一个模型用两套流程修复相同的故障。一个补丁修了空购物车却破坏折扣，另一个通过了两类测试。这对带有验证结果的轨迹可以用于构建训练样本。

选一个你遇过两次的问题，写下触发条件、一条操作步骤和一个能验证成功的信号。再列出两道测试题，至少一道从未用来写这条 Skill。

展开参考做法

例如整理视频时遇到重名。先用时长和文件哈希识别重复，再让人工核对。留出两种情况来测，一种是同名但内容不同，另一种是内容相同但文件名不同。对比启用 Skill 前后的误判数。
